# 常见问题

## 面板打不开

在面板服务器查看服务和日志：

```bash
sudo nekopassctl panel status
sudo nekopassctl panel logs
```

先确认 PostgreSQL 集群正在运行，再确认网页监听端口和云安全组。通过域名访问时，也要检查 [HTTPS 与反向代理](./proxy.md)设置。若重启服务器后面板没有启动，可执行 `sudo nekopassctl panel enable` 设置自启，再运行 `sudo nekopassctl panel start`。

## 节点连不上面板

在节点服务器运行 `sudo nekopassctl agent logs`。如果安装命令无法生成，检查面板「系统设置」中的节点连接地址、端口和安装下载地址。

| 日志或现象 | 怎么排查 |
| --- | --- |
| `error reading server preface: EOF` | 核对是否填了节点控制端口，以及 URL 的 `http://` 或 `https://` 是否与实际配置一致。默认网页端口为 8080，控制端口为 9443。 |
| HTTPS 证书提示未知 CA | 检查面板域名的完整证书链及节点的系统根证书。节点连接要求公共 CA 证书。 |
| 更新密钥后离线 | 执行 `sudo nekopassctl agent configure` 更新地址或密钥，再重启 Agent。 |
| 节点状态停在更新中 | 检查主控连接和节点更新日志，以面板收到的实际节点版本为准。 |

详细设置见[安装节点](./node.md#密钥与连接)。

## 节点在线，转发不通

1. 确认规则已启用，入口节点已同步。用户选不到入口时，检查节点是否允许作入口，以及用户是否获准使用该节点组。
2. 核对客户端连接的入口端口。从负责连接目标的节点检查目标地址是否可达。直转查入口，中转查出口。
3. 检查用户有效期、流量额度，以及目标地址是否被[转发安全](./security.md)限制。
4. 规则提示节点需升级时，按[节点升级](./node.md#升级)操作。有出口节点组时也需要核对出口的 Agent 版本。

TLS 中转失败时，检查出口端口、证书有效期以及 SNI 是否匹配证书域名。自动申请证书失败时，HTTP 验证检查域名解析和公网 80 端口，DNS 验证检查服务商凭据和权限。

接收 PROXY Protocol 无法开启时，由管理员在「系统设置 → 转发安全」添加可信来源 CIDR，再修改规则。

## 邮件或付款有问题

- 收不到注册邮件时，检查 SMTP 地址、连接方式、授权码、发件邮箱和垃圾邮件目录。重发前等冷却时间结束。
- 已付款但余额未更新时，检查网关能否向面板发送付款通知，以及商户配置和待支付订单。余额以网关通知入账为准。
