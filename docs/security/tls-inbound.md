# TLS 入站

多个用户的 TCP 规则可以共用一个入口端口，节点按客户端发送的 SNI 域名选择规则。入口终止 TLS，把解密后的数据发送到规则目标；各规则独立统计流量、执行限制和启停。

## 管理员配置

打开「节点管理 → 编辑节点 → TLS 入站」，新增共享入口，填写名称、端口和证书域名。端口可以使用 `443`，不受普通规则的可分配端口范围限制。

| 配置项 | 用途 |
| --- | --- |
| 启用 | 开关整个共享入口，保留入口及关联规则。 |
| 证书域名 | 单个域名或 `*.example.com`；用户的 SNI 必须在证书覆盖范围内。 |
| 证书模式 | 自动生成自签名、导入证书、DNS 自动申请或 HTTP 自动申请。自动申请的邮箱及 DNS 凭据填写方式见 [TLS](./tls.md)。 |
| 允许的 SNI 范围 | 一行一个域名。`example.com` 允许自身及子域名，`.example.com` 仅允许子域名；留空以证书覆盖范围为准。 |
| 最低 TLS 版本 | 允许客户端使用的最低版本，默认 TLS 1.2。 |
| 接受 Proxy Protocol | 默认关闭。开启后客户端须在 TLS 握手前发送 PROXY v1 / v2 头，自动识别版本；先在「系统设置 → 转发安全」配置可信来源网段。 |
| 并发握手上限、握手超时 | 控制尚未完成 TLS 握手的连接数量和等待时间。 |
| 拒绝没有 SNI 的连接 | 默认开启。关闭后，无 SNI 连接也可以使用管理员默认规则。 |
| 未知 SNI | 拒绝连接，或转发到本入口下的管理员默认规则；仍需满足 SNI 允许范围。 |
| 仅允许 TLS 入站 | 此节点的普通 TCP 规则停止转发，TCP 规则须选择共享 TLS 入口；UDP 不受影响。 |

同一节点的共享 TLS 入口、普通 TCP 规则及 TCP 隧道监听不能占用同一端口。暂停的子规则仍保留 SNI，其他用户不能占用该域名。

## 用户创建规则

在「转发规则」选择 TCP、入口和出口，将「入站方式」设为「共享 TLS 入站」，选择共享入口并填写 SNI 域名，一行一个。监听端口直接使用管理员配置的共享端口。

客户端连接该入口地址与端口，并发送规则填写的 SNI。使用公开 CA 证书时按正常 TLS 验证；使用自签名证书时，管理员可在共享入口列表点击「复制证书」，将公开证书交给用户配置客户端信任。

高级选项中的「入站 ALPN」用于协商目标应用的协议，例如 `http/1.1`。留空不指定 ALPN。

## 回源 TLS

默认将解密后的 TCP 数据发送到目标。如果目标自身使用 TLS，在规则高级选项开启「回源 TLS」。

| 配置项 | 用途 |
| --- | --- |
| 回源 SNI | 发送给目标服务的域名，留空使用当前目标地址中的域名。 |
| 回源 CA | 私有 CA 的公开根证书，留空使用系统信任的公开 CA。 |
| 回源 ALPN | 留空沿用入站协商的协议，也可手动指定。 |

入口 TLS、入口到出口的隧道加密、目标服务的回源 TLS 分别配置。选择出口后，回源 TLS 通过该出口连接目标。

TLS 入站和回源 TLS 的配置使用「Nekopass 完整备份」导入导出。
